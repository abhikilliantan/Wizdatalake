DataLakeSkM Architecture

Four-layer view: Presentation, sources, the System Integration section under active delivery, and the storage / catalog foundation.

Presentation Apps / CRM / Files Databases System Integration (NOW) Event-driven Event-streaming MinIO lake Catalog DB

A · Presentation layer

Ops dashboard, OpenAPI docs, catalog explorer, MinIO console, and BA/PM volume reports. Reads from the lake and catalog — does not write source data.

C · System Integration (NOW)

Active MVP build: integration hub, FastAPI webhooks, Redpanda consumer, file + DB extract connectors, shared envelope, and ObjectStorage writes.

① Event-driven

CRM and app webhooks via FastAPI adapters. Best for discrete state changes (Salesforce, HubSpot, custom apps).

② Event-streaming

High-volume producers and future CDC publish to Redpanda; the consumer batch-flushes into MinIO.

D · Lake + catalog

All integration paths land partitioned, tagged objects in MinIO. Platform PostgreSQL tracks events and checkpoints for the presentation layer.
